# 政党の系譜 設計案 (未実装)

明治の帝国議会開設 (1890) から現在までの政党の成り立ち・合流・分裂・改称・解党、与党だった期間、議席数を見せるための設計案。
**表示は今のタイムライン (`web/index.html` の「タイムライン」) を過去へ延ばす形にする。** 初めは今に近い時期を出し、
左へスクロールし続けると時代をさかのぼり、1945 年以降の現代、さらに明治〜1945 の近現代まで見られる。
今の情報を求める人には過去はあまり要らないので、過去は左へスクロールしたときにだけ読み込む。

- 状態: 設計案。コードは未変更 (2026-11-23 作成、同日 利用者の意見を受けて改訂: 別ページ案 → タイムラインの延長、照合を必須に)
- 調べたこと: データ源のライセンス・取得方法・robots.txt・網羅範囲 (2026-11-23 時点で各サイトを確認。確認できなかった点は「未確認」と書く)
- 関連: タイムラインの「左へスクロールすると古い時期を `/api/timeline` から取って左に足す」仕組みは本体側で実装中。この文書はその上に系譜を載せる設計だけを書く

## 1. 結論 (先に要点)

1. **系譜の骨組みは手で整えた JSON を正とする。** Wikidata (CC0) から下書きを1回だけ作り、日付と関係は機関の所蔵資料で照合したものだけを「照合済み」にする (5 も参照)。
   一つのデータ源で 1890〜現在の系譜・議席・与党を揃えられるものはない。
2. **議席は総選挙ごとの当選者数 (衆議院) を基本とし、照合元を値ごとに持つ。** 総務省の Excel は 2005 年以降だけなので、
   それより前は国立国会図書館の資料 (『議会制度百年史 院内会派編』など) を見て手で写す。
3. **与党は内閣ごとの与党の表 (`cabinets`) で持つ。** 首相官邸「歴代内閣」の在職期間を骨にし、与党の構成は別の資料で付ける。
   `source/actors.json` の `ruling` はこの表と食い違わないかを検査で確かめる (タイムラインは系譜のデータを読まない)。
4. **画面はタイムラインの延長にする (別ページにしない)。** 行 (レーン) は時代とともに入れ替わり、その時期にあった党だけが並ぶ。
   合流・分裂・改称は行と行をつなぐ線で示す。左へスクロールすると過去の時期を読み込んで左に足す (既定は今に近い時期)。
5. **データは確実な資料を持つ機関 (国立国会図書館・国立公文書館・博物館など) の所蔵資料で照合することを必須にする。**
   レコードごとに照合の状態 (未照合 / 照合済み＋照合先) を持ち、画面でも示す。未照合の値は「未照合」と分かる形でしか出さない。
6. 最初は **1945〜現在の衆議院** から始め、帝国議会期 (1890〜1945) は第2段階で足す。貴族院・参議院の会派は第3段階。

### 2.2 Wikidata の確認結果 (2026-11-23)

- 日本 (P17=Q17) の政党 (P31/P279* Q7278): **178 件**。結成日 (P571) あり 142 件 (80%)、解散日 (P576) あり 75 件、
  前身・後身のいずれかの関係あり 85 件 (48%)
- 議席数 (P1410) はほぼ無い (日本の政党で 5 党・9 件。自民党は 0 件)。**議席には使えない**

- 見つかった問題 (そのまま使えない理由):
  - 社会党の右派・左派 (1951 分裂) が日本社会党と結ばれておらず、結成日は 1948-01-01 と誤っている。右派には解散日が無い
  - 日付の精度がまちまち (年だけのものが YYYY-01-01 で入る)。値ごとに精度 (`psv:` の precision) を見る必要がある
  - 関係の付け方が揃っていない (replaces と follows の両方、merged into は「既存の党に吸収」だけ)。種類は手で付け直す
  - 戦前は薄い (立憲自由党 → 自由党 → 憲政党 → 立憲政友会 の流れが通しでは結ばれていない)
- 取得の作法: Wikimedia の User-Agent 方針で、自動取得には連絡先入りの User-Agent が求められる (汎用の UA は 403 になりうる)。
  一方で `query.wikidata.org/robots.txt` は `/sparql` を Disallow している。このプロジェクトは robots.txt を守る方針なので、
  **SPARQL エンドポイントは使わず、`Special:EntityData/Qxxx.json` (robots.txt で Allow) を 2 秒間隔で、対象の QID だけ取る**か、
  公式ダンプ (`dumps.wikimedia.org`) を1回取って手元で絞る。どちらも取り込みは1回きりで、結果をリポジトリに置く。
  連絡先は個人のメールではなく、プロジェクトの URL などにする

### 2.3 照合の要件

**系譜の党・関係・与党・議席は、確実な資料を持つ機関 (国立国会図書館・国立公文書館・博物館・議会の資料館など) の所蔵資料で照合したものだけを「照合済み」にする。**
Wikidata や Wikipedia、記憶で書いた値は、どれだけもっともらしくても「未照合」のまま扱う。

照合先の順位 (食い違ったとき):

1. 当時の公的な記録: 官報、議会の公式記録 (会議録・議員名簿)、届出などの公文書 (国立国会図書館・国立公文書館などの所蔵)
2. 議会・国立国会図書館の刊行物: 『議会制度百年史』『議会制度七十年史』、衆参の資料、Web NDL Authorities
3. 総務省の選挙結果 (2005 年以降)、政党自身の党史・発表 (党の公式の記録。他の資料とも照らす)
4. Wikidata (下書き。これだけでは照合済みにしない)

- 照合済みにするには、1 か 2 の照合先が少なくとも1つ要る (2005 年以降の議席は 3 の総務省でよい)
- 照合先どうしで食い違うときは `disputed` にし、両方の値と照合先を残す (どちらかに決めない)
- 照合は人が資料を見て行い、照合先 (機関・資料名・識別子・ページ・閲覧方法) と照合した日を記録する (3.7)

### 2.4 機関の資料へのアクセスの方法

照合には、インターネットで読めない資料が多い (『議会制度百年史』などは館内限定・送信限定)。手に入れ方の候補と、使える場面:

| 機関 | 資料 | アクセスの方法 | 備考 |
|---|---|---|---|
| 国立国会図書館 | NDLデジタルコレクション (百年史・七十年史・党史、官報 など) | (1) インターネット公開分はそのまま閲覧。(2) **個人向けデジタル化資料送信サービス**: 本登録 (日本国内居住) すると、送信対象資料を自宅で閲覧できる。(3) **図書館向けデジタル化資料送信サービス**: 参加している大学図書館・公共図書館で閲覧。(4) 東京本館・関西館での館内閲覧 | 百年史・七十年史は館内限定＋送信対象。自動取得・複製の再配布はしない。どの資料がどの公開範囲かは pid ごとに確認する |
| 国立国会図書館 | 紙の資料、複写 | **遠隔複写サービス** (登録利用者が必要なページの複写を郵送で取り寄せる)。**レファレンス** (所属する図書館を通じて照会) | 何ページを見るか先に絞ってから申し込む |
| 国立公文書館 | 公文書 (内閣の記録など) | 国立公文書館デジタルアーカイブ、アジア歴史資料センター (1945 年以前の公文書をネットで閲覧)、閲覧室での閲覧・複写の申込み | 政党の結成・解散の届出がどこまで残っているかは**未確認** |
| 衆議院・参議院 | 議会の資料、憲政記念館 (議会政治の資料) | 公開資料の閲覧。分からない点は事務局への問い合わせ | 憲政記念館の開館状況・資料の閲覧方法は**未確認** |
| 大学の資料センター・博物館 | 近代の政治資料、新聞・雑誌 (例: 東京大学 近代日本法政史料センター) | 所属大学の図書館を通じた紹介状・閲覧の申込み | 所蔵と利用条件は機関ごとに**未確認** |
| 各政党 | 党史、結党・解党の記録 | 党の刊行物 (国立国会図書館にもある)、党本部への問い合わせ | 党自身の記録なので他の資料と照らす |

進め方の案:

1. まず国立国会図書館の**本登録**を行い、個人送信で百年史・七十年史を読めるようにする。所属大学の図書館が図書館送信の参加館かも確かめる (**未確認**)
2. 照合する範囲 (例: 1945〜1960) を決め、見るページを NDL Search の目次で絞る。送信で読めない資料は遠隔複写で取り寄せる
3. 資料で決着しない点 (合流か吸収か、結成日の違いなど) は、所属図書館のレファレンスを通じて照会するか、所蔵機関に問い合わせる。
   問い合わせでは、このプロジェクトの目的 (出典付きで政党の系譜を示す) と、知りたい点を具体的に書く
4. 写した事実は、照合先と一緒に `source/genealogy/*.json` に記録する (資料の本文・画像は保存も公開もしない)

照合は機関の資料を見る人の手作業になり、時間がかかる。照合が進んでいない時期も、画面では「未照合」と示した上で系譜を見せる
(未照合の線・値は破線や薄い色。4.2)。照合済みの範囲は README か STATUS.md に書く。

### 3.2 政党 (`parties.json`)

```json
{
  "id": "jiyuto-1950",
  "name": "自由党",
  "kana": "じゆうとう",
  "aliases": ["吉田自由党"],
  "start": "1950-03-01",
  "end": "1955-11-15",
  "kind": "party",
  "family": "conservative",
  "color": null,
  "actor": null,
  "wikidata": "Q4981144",
  "ndla": null,
  "note": "民主自由党と民主党連立派の合同で結成",
  "sources": [{"title": "Wikidata", "url": "https://www.wikidata.org/wiki/Q4981144"}],
  "verification": {"status": "unverified", "checked": []}
}
```

- **1つの名前の1つの期間を1ノード** にする。同じ名前の別組織 (民主党 1996 / 1998、立憲民主党 2017 / 2020、日本自由党 1945 / 1953) は `id` に年を付けて分ける
- `start` / `end` は `YYYY` / `YYYY-MM` / `YYYY-MM-DD` (タイムラインと同じ書き方)。`end: null` は存続中
- `kind`: `party` (政党) / `group` (院内会派のみ) / `association` (大政翼賛会・翼賛政治会など、政党ではない政治結社)
- `family`: 色の系統を決める大まかな流れ (`conservative` / `liberal` / `centrist` / `socialist` / `communist` / `other`)。
  **思想の評価ではなく、色分けの都合**であることを画面に書く
- `actor`: `source/actors.json` の `id` (今ある党だけ)。色と現在の名前はそちらを使う

### 3.3 関係 (`links.json`)

```json
{"type": "merge", "from": ["jiyuto-1950", "nihon-minshuto-1954"], "to": "jimin-1955",
 "date": "1955-11-15", "label": "保守合同", "sources": [...], "verification": {"status": "unverified", "checked": []}}
```

| `type` | 意味 | from → to | 図での描き方 |
|---|---|---|---|
| `found` | 新しく結成 (前身なし) | — → 1 | 線の始まり |
| `merge` | 複数の党が合わさって**新しい党**を作る | n → 1 (新) | 流れが1本に合わさる |
| `absorb` | 既存の党に**吸収**される (相手は続く) | 1 → 1 (既存) | 合流先の線に入る |
| `split` | 1つの党が**割れて**元の党がなくなる | 1 → n | 流れが分かれる |
| `breakaway` | 一部の議員が**離れて**新党を作る (元の党は続く) | 1 → 1 (新) | 細い枝が分かれる |
| `rename` | 改称 (組織は同じ) | 1 → 1 | 同じ行のまま色・名前だけ替える |
| `dissolve` | 解党 (後継なし) | 1 → — | 線の終わり |
| `return` | 離れていた議員が元の党に戻る | 1 → 1 (既存) | 枝が元の線に戻る |

- `share` (任意): `breakaway` / `return` / `absorb` で動いた衆議院議員の数。線の太さに使う
- `partial: true`: 党の一部だけが加わった合流 (例: 民主党の連立派だけが自由党の結成に加わった)
- 関係の種類の判断が資料で分かれるもの (合流か吸収か、など) は `note` に書き、出典を両方付ける

### 3.4 内閣と与党 (`cabinets.json`)

```json
{"id": "yoshida-1", "name": "第1次吉田内閣", "pm": "吉田茂",
 "start": "1946-05-22", "end": "1947-05-24",
 "ruling": ["nihon-jiyuto-1945", "shinpoto-1945"],
 "support": [],
 "sources": [{"title": "首相官邸 歴代内閣", "url": "https://www.kantei.go.jp/jp/rekidainaikaku/..."}],
 "verification": {"status": "unverified", "checked": []}}
```

- 期間は首相官邸の在職期間。`ruling` は閣僚を出した与党、`support` は閣外協力
- 政党内閣でない内閣 (藩閥・官僚・軍人内閣、東久邇宮・幣原内閣など) は `ruling: []` とし、画面では「政党内閣でない」と示す
- 党ごとの与党期間は、この表から計算する (党が `ruling` に入っている内閣の期間をつなげる)

### 3.5 総選挙 (`elections.json`)

```json
{"id": "shu-1955", "chamber": "衆", "date": "1955-02-27", "number": 27, "seats": 467,
 "results": {"nihon-minshuto-1954": 185, "jiyuto-1950": 112, "saha-shakai-1951": 89, "uha-shakai-1951": 67,
             "rono-1948": 4, "jcp": 2, "_others": 8},
 "sources": [{"title": "(記憶による下書き)"}],
 "verification": {"status": "unverified", "checked": []}}
```

- 選挙時の党派別当選者数。選挙後の入党・会派の出入りは含めない (`_others` は諸派・無所属をまとめたもの)
- 会派 (国会内の議員の集まり) の議員数は党と一致しないので、第3段階で別に持つ (`groups.json`)

### 3.6 `source/actors.json` とタイムラインとのつなぎ方

- **行のつながり:** `parties.json` の `actor` で、今の党 (タイムラインの行) を指す。タイムラインを左へさかのぼると、
  その行は `actor` の党から `links.json` を後ろへたどった前身の党に続く (4.2)
- **データは分ける:** タイムラインの出来事 (`events`、LLM で取り出したもの) と系譜 (人が照合した台帳) は別のファイル・別の API。
  `timeline/` のコードは系譜のファイルを読まず、画面で重ねて描く。系譜の読み込みと行の位置の計算は別のモジュール (`genealogy/`、仮) に置く
- **色:** `actor` のある党は `actors.json` の `color` を使う。前身の党は、後身の色を薄くしたもの (同じ系統の色相で明るさを変える) を自動で付け、
  `parties.json` の `color` で上書きできる。今の党の色が近いものは actors と同じ問題を持つので、行の上に名前を常に書く
- **与党期間:** 正は `cabinets.json`。`actors.json` の `ruling` (2012 年以降だけ入っている) は、
  「cabinets から計算した期間と一致するか」を検査するテスト (`tests/test_genealogy.py` など) で確かめる。
  タイムラインが 2012 年より前の出来事を出すときの与党・野党の印 (`view.role`) も、cabinets から計算した期間を使うようにする (手で二重に書かない)
- 例: `actors.json` の公明党 `ruling: [["2012-12-26","2025-10-10"]]` は、cabinets では第2次安倍内閣〜石破内閣の `ruling` に公明党が入っていることと対応する。
  1999-10-05〜2009-09-16 の期間も cabinets にはあり、左へさかのぼるとその期間に与党の縁取りが付く
- **名前の揺れ:** actors の `match` (会議録の会派名) と系譜の `aliases` は別物として持つ (会派名は党名と一致しないため)。
  過去の会議録の発言を過去の党の行に割り当てるには、時期ごとの会派名の対応が要る (第3段階の `groups.json`)

### 3.7 照合の状態 (すべてのレコードに共通)

党・関係・内閣・総選挙の各レコードに `verification` を持つ。上の例の `verification` はこの形。

```json
"verification": {
  "status": "verified",
  "checked": [
    {"institution": "国立国会図書館",
     "title": "議会制度百年史 院内会派編 衆議院の部",
     "id": "pid:9673682", "page": "123",
     "access": "個人向けデジタル化資料送信",
     "checked_at": "2026-12-01", "checked_by": "照合者の呼び名",
     "result": "一致"}
  ],
  "fields": {},
  "note": ""
}
```

| `status` | 意味 | 画面 |
|---|---|---|
| `unverified` | 未照合 (Wikidata・記憶などからの下書き) | 破線・薄い色、「未照合」 |
| `verified` | 2.3 の要件を満たす照合先と一致した | 通常の表示。詳細欄に照合先 |
| `disputed` | 照合先によって値が違う | 印を付け、詳細欄に両方の値と照合先 |

- `sources` は値を**どこから持ってきたか** (下書きの出どころ)、`verification.checked` は**何で確かめたか**。分けて持つ
- `fields`: レコードの一部の値だけ状態が違うとき (例: 結成日は照合済み、解党日は未照合) に、値ごとの状態を書く
  (`{"end": {"status": "unverified"}}`)。書かない値はレコードの `status` に従う
- `result`: `一致` / `訂正` (照合で値を直した。直す前の値は `note` に書く) / `相違` (`disputed` の根拠)
- `checked_by` は実名やメールにしない (呼び名かイニシャル)
- 検査 (テスト) で、`verified` なのに `checked` が空のもの、`checked` が Wikidata だけのものを誤りにする
- 画面と API は `status` を必ず返し、未照合を照合済みと同じ見た目で出さない

## 4. 画面: タイムラインを過去へ延ばす

### 4.1 方針 (利用者の意見を受けて決めたこと)

- **別ページにしない。** 今のタイムライン (行=主体、横=時間、今日の線) の横軸をそのまま過去へ延ばす
- **既定は今に近い時期。** 今の情報を求める人の画面は今と変わらない。過去は左へスクロールしたときにだけ読み込む
  (本体側で実装中の「左端に近づいたら古い時期を `/api/timeline` から取って左に足す」仕組みに乗せる)
- **見せたいのは二つ。** (1) 党と党のつながり (合流・分裂・改称)、(2) 見たい人には個々の情報 (結成日・与党だった内閣・議席・出典・照合の状態)
- **行は時代とともに入れ替わる。** その時期にあった党だけが行として並び、なくなった党の行は終わり、新しい党の行が始まる

### 4.2 見え方

```
 ← 左へスクロールすると過去を読み込む                                      今日の線 →│
 1950         1955         1960     …     2017        2020        2026          │
 自由党 ━━━━━━┓                          立憲民主党(2017) ━━┓                    │
              ┣━ 自由民主党 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ ○ ○ │  ← 今の行 (actors.json)
 改進党 ━ 日本民主党 ┛                    国民民主党(2018) ━━┻━ 立憲民主党(2020) ━━━ □ │
 右派社会党 ━━┓                                         ┗━ 国民民主党(2020) ━━━ □ │
              ┣━ 日本社会党 ━━━━┳━━━━━━  …                                          │
 左派社会党 ━━┛                 ┗━ 民主社会党 …                                     │
```

- **行 (レーン):** 今ある党の行は今のタイムラインの行 (`actors.json`) と同じ。左へ進んで、その党の前身の時期に入ると、行はその前身の党の名前・期間に続く
  (改称は同じ行のまま名前が替わる)。前身が複数あるとき (合流) は、行が上下に分かれて左へ延びる
- **つながりの線:** 合流・分裂・離脱・復帰・吸収は、関係の日付の位置で行と行を結ぶ斜めの線にする。線の太さは動いた議員の数 (`share`) か、
  直前の総選挙の議席。改称は線を引かず、行の上の名前の切り替わりと小さな印で示す
- **与党の期間:** 今と同じく ○ 与党 / □ 野党 で、行の帯に縁取りを付ける (`cabinets.json` から計算)。政党内閣でない時期は帯を付けず、上の時代帯に「政党内閣でない」と書く
- **時代帯:** 横軸の上に内閣・時代 (帝国議会期、占領期、55年体制、など) の帯を出し、今どこを見ているか分かるようにする。年への移動 (1890 / 1945 / 1955 / 1993 などへ飛ぶ) も付ける
- **詳細:** 行・線をクリックすると、党の結成・解党日、前身・後身、与党だった内閣、総選挙の議席、**出典と照合の状態**を横の欄に出す
- **出来事:** 過去の時期に収集済みの資料 (国会会議録など) から取り出した出来事があれば、今と同じく行の上に印で出す。2026 年より前は資料がほとんど無いので、
  多くの時期は行と線だけになる。それで構わない (系譜を見せるのが目的)
- **未照合の表示:** 未照合の党・線・値は破線や薄い色にし、凡例に「未照合」と書く。照合済みでも資料により異なるもの (`disputed`) は印を付けて詳細欄に両説を出す

### 4.3 行の並べ方

- 時期ごとに「その時期にあった党」だけを行にする。行の数は時代で変わる (1955 年ごろは 5 行前後、1990 年代の再編期は 10 行以上)
- 並び順は今の `actors.json` の順を右端の基準にし、左へは系譜をたどって前身を後身の行の近くに置く。どの今の党にもつながらない党 (解党で終わった党) は、
  つながりの近い党の近くに入れる。交差が多くて見にくいところは `parties.json` の `row` (任意) で手で直す
- 行の位置はサーバーで計算して返す (画面は描くだけ)。`/api/genealogy` (仮) は `date_from` / `date_to` を受け、その範囲の党・関係・与党・総選挙と行の位置を返す。
  タイムラインが左に期間を足すときに、`/api/timeline` と並べて呼ぶ

### 4.4 狭い画面

今のタイムラインは狭い画面で一覧になる。系譜も同じく、一覧の中で党名を押すと前身・後身を縦の木 (前身が上、後身が下) で出す。
横スクロールの図は出さない。

### 4.5 今のタイムラインとの分担

| | 今のタイムライン | 系譜 (この設計) |
|---|---|---|
| データ | `events` (資料から LLM で取り出した出来事)、`actors.json` | `source/genealogy/*.json` (人が照合した台帳) |
| API | `/api/timeline` | `/api/genealogy` (仮) |
| 画面 | 同じタイムライン。出来事の印 | 行の延長、つながりの線、与党の縁取り、時代帯 |
| 更新 | 定時更新 (`events`) | 手で照合して足す。定時更新しない |

LLM の取り出した出来事と、人が照合した系譜は、データの確かさが違うので混ぜない (同じ画面に重ねて描くだけ)。

### 4.6 検討して採らなかった案

- **別ページの系統図:** 利用者の意見で、タイムラインの延長にすることにした。系統図の描き方 (合流・分裂の線、議席を線の太さに) は 4.2 に引き継ぐ
- **総選挙ごとの議席の積み上げ図:** 選挙の間の合流・分裂が見えにくい。議席は詳細欄と線の太さで見せる
- **党を選んでたどる一覧だけ:** 全体のつながりが見えない。狭い画面用 (4.4) にだけ使う

### 4.7 段階

1. 1945〜現在の衆議院。行の延長とつながりの線、与党の縁取り、詳細欄
2. 総選挙の議席を線の太さに使う
3. 1890〜1945 (帝国議会、衆議院)。大政翼賛会などは `association` として点線で描く
4. 貴族院・参議院の会派 (`groups.json`)

## 5. 取得・作成の手順 (実装するとき)

1. **下書き:** `python main.py genealogy draft` (仮) で、Wikidata の対象 QID を `Special:EntityData/Qxxx.json` から 2 秒間隔で取得し、
   `data/genealogy/wikidata_draft.json` を作る。最初の QID の一覧は手で作る (SPARQL は robots.txt で Disallow のため使わない)。1回だけ実行する
2. **整える:** 下書きから `parties.json` / `links.json` に手で写し、関係の種類を付け直す。この時点ではすべて `verification.status: "unverified"`
3. **照合:** 2.3 の要件に沿って、2.4 の方法で機関の資料を見て照合し、`verification.checked` に照合先を書いて `verified` (食い違えば `disputed`) にする。書名・pid・ページ・閲覧方法を記録し、本文の複製はしない
4. **議席:** 2005 年以降は総務省の Excel (選挙ごとに表の形が違う) から写す。それより前は百年史などから手で写す
5. **検査:** テストで、関係の両端の党が存在する、期間が関係の日付と矛盾しない (合流の日に from が終わり to が始まる)、
   総選挙の合計が定数以下、`actors.json` の `ruling` が cabinets と一致する、を確かめる

- 画面とそのデータは、照合が済む前から出してよい (未照合と分かる表示で)。照合が進むと表示が変わる
- 自動で定時更新はしない (歴史のデータで、変わるのは新党の結成・解党のときだけ。そのときに手で足す)
- Wikidata・NDL 典拠の値は画面に出すとき出典として名前を出す (NDL 典拠は出典表示が利用条件)
